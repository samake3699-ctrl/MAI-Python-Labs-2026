# Лабораторная работа № 1
## Приём работ и расширяемые анализаторы

**Траектория:** Python Core  
**Уровень:** основной  
**Язык реализации:** Python 3.10+

### 1. Описание проекта

Проект представляет собой прототип системы онлайн-школы для приёма и анализа лабораторных работ студентов.

Система позволяет:

- импортировать работы студентов из файлов JSONL;
- проверять структуру и корректность входных данных;
- проверять идентификаторы, временные метки и декларации использования ИИ;
- обнаруживать дубликаты и конфликты идентификаторов;
- сохранять принятые работы во временном репозитории в памяти;
- запускать независимые анализаторы через реестр;
- сравнивать код с разрешёнными шаблонами.

Код студентов не выполняется.

### 2. Архитектура проекта

Исходный код расположен в каталоге `src/school/`.

Основные модули:

| Модуль | Назначение |
|---|---|
| `models.py` | Модели `Submission` и `AIDeclaration` |
| `parser.py` | Разбор JSON и импорт JSONL |
| `validation.py` | Проверка данных и формирование ошибок |
| `repository.py` | Хранение работ и обнаружение дубликатов |
| `hashing.py` | Вычисление хеша содержимого |
| `cli.py` | Интерфейс командной строки |
| `analysis.py` | Контракты анализа и структуры результатов |
| `analyzers.py` | Реализации анализаторов |
| `registry.py` | Реестр анализаторов и центральный сервис |
| `sources.py` | Источники шаблонов в памяти и JSONL |

### 3. Установка

Требуется Python версии 3.10 или выше.

Создание виртуального окружения в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e .
```

### 4. Запуск импорта

Пример импорта корректных данных:

```powershell
python -m src.school.cli submissions.jsonl
```

Пример импорта некорректных данных:

```powershell
python -m src.school.cli invalid_submissions.jsonl
```

Результат импорта выводится в формате JSON. Ошибки отдельных строк не должны останавливать обработку всего файла.

### 5. Анализаторы

**LengthAnalyzer** подсчитывает непустые строки текста и кода. Результат содержит пояснение, а значение `score` равно `null`.

**TemplateAnalyzer** сравнивает строки кода с разрешённым шаблоном, вычисляет показатель сходства и возвращает сведения о совпавших строках.

Совпадение с разрешённым шаблоном само по себе не является доказательством нарушения.

Для подключения анализаторов используется `AnalyzerRegistry`. Центральный сервис не содержит отдельной логики для каждого конкретного анализатора.

### 6. Источники данных

Реализованы два источника шаблонов:

- `InMemoryTemplateSource` — хранение данных в памяти;
- `JSONLTemplateSource` — чтение шаблонов из JSONL-файла.

Файловый источник поддерживает контекстный менеджер для управления ресурсами.

### 7. Тестирование

Запуск автоматических тестов:

```powershell
python -m unittest discover -s tests -v
```

Последний результат проверки:

```text
Ran 20 tests in 0.049s

OK
```

Проверяются обработка корректных и некорректных данных, дубликаты, конфликты, анализаторы, управление ресурсами и другие сценарии.

### 8. Демонстрационные данные

- `submissions.jsonl` — пример корректной работы;
- `invalid_submissions.jsonl` — примеры некорректных данных;
- `assignments.json` — пример описания задания;
- `templates.jsonl` — разрешённые шаблоны.

Файл `assignments.json` включён как демонстрационные данные и не загружается автоматически текущей реализацией.

### 9. Ограничения

- Репозиторий хранит данные только в оперативной памяти.
- Нет HTTP API и постоянной базы данных.
- Анализаторы работают синхронно.
- Сравнение с шаблонами основано на точном совпадении строк.
- Система не использует модель машинного обучения и не выполняет код студентов.
- Файл `assignments.json` пока не интегрирован в автоматическую загрузку контекста.
